# Аудит FinanceAcademy — 16 октября 2026

Сайт: https://finacademy.kz. Опубликована версия `audit-20261016-3`, каталог `/opt/finance-academy/releases/20261016-3`. Проверены экзамен, восстановление связи, вкладки, потоки, импорт, назначения, запросы интерфейса, PostgreSQL и обслуживание VPS. Нагрузочные прогоны не запускались. Это функциональный и архитектурный аудит, не независимый пентест и не подтверждение часовой нагрузки 50 пользователей.

## Сильные стороны

- Сервер рассчитывает оценку и срок; правильные ответы скрыты от студента. Снимок вопросов сохраняет старый экзамен при изменении банка.
- Версии сохранений, повторяемое завершение без повторной оценки, устойчивые ID событий прокторинга. Запуск в PostgreSQL защищён транзакционной блокировкой и пределом 50 непросроченных активных попыток.
- Создание потоков из ФИО, массовый сброс паролей, обязательная смена временного пароля и отзыв сессий. Повтор создания не создаёт второй поток.
- Четыре основных банка МСФО/МСФООС RU/KZ: по 200 вопросов, случайные 25, максимум 100 баллов, порог 50.
- API за Nginx на loopback, HTTPS, ежедневное резервирование и автоматическое обновление сертификата. Воспроизводимые сборка и проверки.

## Запросы и сохранение

Пустое продление спокойной попытки: раньше примерно 15–19 секунд, теперь 30–35 секунд с разбросом между клиентами. Для средних 17 и 32,5 секунды это **около 48% меньше именно пустых продлений**, а не всех запросов сайта. Для 50 спокойных попыток за час — примерно 10,6 тыс. против 5,5 тыс. таких запросов, без ответов, событий, старта и завершения. Это расчёт по интервалам, не нагрузочное измерение и не p95.

Изменённые ответы не ждут фонового продления: отправляются примерно через 2–3 секунды, в последние 20 секунд — сразу. При частых ответах запросов может стать больше, чем при прежнем длинном интервале сохранения: это осознанный выбор в пользу своевременного подтверждения ответа. События прокторинга могут требовать отдельного запроса; скрытие страницы — дополнительной идемпотентной отправки с keepalive.

Одинаковые GET объединяются только пока запрос выполняется. Длительного кэша персональных результатов и прав доступа нет; изменение данных очищает очередь повторного использования.

## Следующие улучшения и оставшиеся ограничения

| Приоритет | Улучшение | Польза / ограничение сейчас |
|---|---|---|
| Высокий | Зашифрованная резервная копия вне VPS и регулярное автоматическое пробное восстановление | Копия на том же сервере не защищает от потери всего сервера; ежедневный интервал допускает потерю изменений после последней копии |
| Высокий | Оповещения о 5xx, ошибках сохранения/копирования, заполнении диска, истечении сертификата | Проблема обнаруживается до жалобы студента; нужны согласованные канал и получатель. Внешние сообщения не подключались |
| Высокий | Архив технических данных с предварительным списком и копией | Старые демонстрационные и нагрузочные студенты/тесты мешают выбору и сводкам. История в этом обновлении не удалялась |
| Средний | Мастер «поток → язык и банки → расписание → таблица доступов», шаблоны назначения | Убирает повторную настройку экзаменов и переходы между экранами |
| Средний | Серверная пагинация и отдельный полный экспорт | Сейчас список ограничен последними 5000 результатами: при росте базы выгрузка из списка будет неполной |
| Средний | Версии административных карточек и сравнение изменений | Два администратора пока могут последовательно перезаписать изменения одной карточки; защита версий ответов студента это не заменяет |
| Средний | Отдельный устойчивый черновик каждой вкладки и журнал спорных восстановлений | Серверные ответы защищены, но локальное хранилище не является независимой резервной копией и может быть очищено/утрачено |
| Средний | Показывать достижение лимита событий прокторинга | Лимит 1000 событий защищает БД; новые события сверх него не добавляются, нужен явный признак усечения журнала |
| Низкий | Единый пояс суточной аналитики, локальные веб-шрифты, разделение большого API-модуля | Дневные графики сейчас агрегируются по UTC; внешние шрифты создают зависимость от стороннего сервиса; большой модуль сложнее сопровождать |

Восстановление старого ID потока использует сохранённое название. При ранее удалённом/переименованном потоке достоверный ID может быть неизвестен; неизвестные связи нельзя придумывать. В текущих данных непустых названий без совпадения не осталось. Новые попытки получают ID непосредственно при старте.

Нельзя гарантировать сохранение ответа на сервере, если интернет отсутствует до конца экзамена. Интерфейс теперь различает локальный выбор и подтверждение сервера, предупреждает об ошибках и позволяет скачать спорную копию. Копия не доказывает правильность ответа и не меняет балл автоматически. Часовая работа 50 студентов и p95 требуют отдельного разрешённого нагрузочного прогона.

Для проверки доступности интерфейса использованы [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md); выводы о системе основаны на исходном коде и описанных проверках.
