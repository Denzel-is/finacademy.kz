# Эксплуатация FinanceAcademy

## Git и публикация

Репозиторий: https://github.com/Denzel-is/finacademy.kz. Он публичный: в нём только исходный код, миграции, синтетические проверки и документация. `.local`, выгрузки, документы заказчика, банки вопросов и резервные копии исключены. Автокоммиты отменены владельцем; автоматического изменения кода или публикации нет.

После клонирования: `npm ci`, `npm run git:setup`. Перед коммитом просмотрите diff, выполните `npm test` и `npm run build:vps`. Hook проверяет подготовленные файлы на известные секреты; pre-push проверяет содержимое HEAD. CI GitHub повторяет проверки и аудит производственных зависимостей с правами только чтения. Проверка секретов не распознаёт любые персональные данные: содержимое новых файлов также должен просмотреть человек.

Пароли, базы и доступы не переносить в Git даже в зашифрованном виде. Никаких force-push, автоматических слияний или автоматического деплоя. Загрузка новой версии VPS выполняется отдельно с копией базы, проверкой PostgreSQL в временной базе и проверкой `/api/ready`, ревизии и рабочего интерфейса. Предыдущий каталог releases сохраняется; базу поверх новых учебных данных автоматически не откатывать.

## Быстрая выдача доступов

1. «Потоки» → «Создать поток»: вставьте нумерованный список ФИО, проверьте и создайте.
2. В том же окне отметьте нужные тесты, укажите минуты и попытки для каждого, общий период доступа. Успешные назначения при повторе не отправляются заново.
3. Выберите способ передачи: «Скачать Excel», «Скопировать» у конкретного студента, «Скопировать все» или «Печать карточек». Сообщение/карточка содержит сайт, ФИО, логин и индивидуальный временный пароль.
4. Передайте каждому только его данные. Общую таблицу храните в защищённом месте и удалите, когда она больше не нужна. Не отправляйте её в общий чат студентов.

Пароли генерируются случайно, по 16 символов, у каждого свой; первая смена обязательна. Существующие пароли повторно не отображаются. Действующие студенческие пароли при обновлении не меняются массово.

Если файл потерялся: откройте студентов нужного потока → «Выбрать найденных» → «Сбросить пароли» → подтвердите. Выбранные получат новые индивидуальные временные пароли; появится новая таблица с теми же способами передачи. Старые сессии завершатся, ответы и результаты сохранятся. Не делайте сброс во время экзамена без необходимости.

При потере ответа сервера на создание потока повтор не создаёт дубликат и не раскрывает секрет повторно: интерфейс предложит явно сбросить пароли. В базе сохраняются хэши; одноразовая выдача не требует хранения открытых паролей.

## Сервер и резервные копии

- HTTPS/Nginx, API только loopback, PostgreSQL через Unix socket; firewall пропускает только SSH/HTTP/HTTPS.
- SSH работает по ключу владельца; парольный вход отключён после проверки отдельного ключевого подключения. Локальный ключ: профиль владельца, `.ssh/finacademy_ed25519`. Не публиковать и не передавать его.
- Ежедневная копия базы в 02:00 UTC, хранение 14 дней, private permissions, блокировка параллельного запуска и SHA-256.
- Еженедельная проверка восстановления в отдельной базе; рабочая база при этом не изменяется.
- Локальная диагностика сервера каждые 15 минут: готовность БД/процесса, место, свежесть копии, состояние проверки восстановления и сертификата. Отчёты: `/var/lib/finance-academy-maintenance/health.json` и `restore.json`. Отчёты не отправляются во внешние чаты.

Внешняя копия на компьютер владельца: `.local/ssh-env/Scripts/python.exe -X utf8 scripts/deploy/offsite-backup.py`. Скрипт проверяет закреплённый ключ SSH, выбирает свежую копию и сохраняет только аутентифицированно зашифрованный файл в `%USERPROFILE%/.codex/backups/finacademy`. Ключ шифрования находится отдельно в `%USERPROFILE%/.codex/private/finacademy-backup.key`. Сам ключ нужно дополнительно сохранить в безопасном независимом месте: без него расшифровать копии невозможно. Первая копия выполнена и проверена; после отмены расписания автокоммитов регулярное копирование на ПК не запускается автоматически.

Для восстановления внешней копии используйте `cryptography.fernet.Fernet` с локальным ключом, записывая расшифрованный dump только в закрытый временный каталог. Сначала восстановите его в отдельную PostgreSQL-базу и проверьте содержимое; не заменяйте рабочую базу без согласованного плана.

## Проверки и ограничения

На входе ограничивается перебор с учётом общей сети группы; нет общего ограничения запросов, мешающего 50 студентам. Размер JSON проверяется по фактически прочитанным байтам. Новые пароли используют PBKDF2-SHA256 600000; прежние хэши совместимы и усиливаются при успешном входе без смены пароля. Сброс также снимает блокировку перебора выбранного аккаунта.

Страница результатов получает 25 строк и агрегаты сервера. Полный экспорт последовательно получает пакеты по 500, без прежнего предела 5000. Он фиксирует границу старта новых попыток; статус уже начатой попытки может меняться во время выгрузки. Для окончательного отчёта дождитесь завершения потока.

Лимит серверного журнала — 1000 событий. Достижение показывается студенту и администратору; отклонённые события остаются в локальной копии и доступны для скачивания, не повторяются бесконечно. Ответы теста продолжают сохраняться независимо от лимита журнала.

Нагрузочные прогоны по указанию владельца выключены. Старую автоматизацию 300 студентов не возобновлять. Наличие функциональных проверок и лимита 50 не подтверждает часовой p95. Полная безопасность требует дальнейших обновлений, контроля доступов и эксплуатационной дисциплины; локальный браузерный черновик не заменяет серверную копию.
