# FinanceAcademy на VPS в Казахстане

Развёрнуто 16.10.2026: https://finacademy.kz. `www` и HTTP перенаправляются на основной HTTPS-адрес. Домен использует DNS Hoster.kz; A-записи основного имени и www указывают на 185.129.49.84. Записи почты не менялись.

## Инфраструктура

- Hoster.kz Cloud 4-4-100: Астана, 4 vCPU, 4 ГБ RAM, 100 ГБ диска.
- Ubuntu 26.04 LTS; Node.js 22.22.1; PostgreSQL 18.6; Nginx 1.28.3.
- Приложение: `/opt/finance-academy/current` → `/opt/finance-academy/releases/20261016-2`.
- Интерфейс обслуживает Nginx из `/var/www/finance-academy`; каталог исходников приложения для Nginx не требуется.
- API работает от непривилегированного пользователя `finacademy`, слушает только 127.0.0.1:3000; systemd `finance-academy.service`, перезапуск при сбое.
- PostgreSQL `finacademy`, одноимённая роль, локальный Unix-сокет и peer-аутентификация, пул до 12 соединений. Пароль базы через интернет не передаётся. Порт 5432 слушает только loopback; firewall открывает 22, 80 и 443.
- Сертификат Let's Encrypt для finacademy.kz/www, первоначальный срок до 14.01.2027; автоматическое продление `certbot.timer` включено.
- Ревизия API: `flows-20261016-2`. Раз в 30 секунд сервер закрывает до 100 просроченных попыток с уже подтверждёнными ответами; это обслуживание приложения, не генератор нагрузки.

## Перенос данных

После первичного импорта Cloudflare переведён в режим обслуживания; затем получен финальный экспорт D1, повторно объединён с PostgreSQL и сверены все поля каждой исходной записи. Обновление источника остановлено до финального снимка. Экспорт SQL и промежуточные JSON находятся только в игнорируемой `.local` и приватных каталогах VPS; они не входят в публичные файлы.

Из Cloudflare перенесены 5 групп, 325 учётных записей, 14 тестов, 820 вопросов, 50 назначений, 2462 попытки, 2111 событий прокторинга, 55 административных событий и 3 настройки. Сохранены идентификаторы, хеши паролей, снимки, ответы и существующие оценки. Сессии и временные лимиты входа не переносились: на новом домене нужен повторный вход. Истёкшие активные попытки после импорта закрывает сервер с сохранёнными ответами.

В обоих учебных тестах МСФО — по 200 вопросов, случайные 25, 60 минут, максимум 100 баллов, проходной порог 50. Подтверждённый ключ №188 — A, 485 000. Реальные тесты при проверке не редактировались.

Одна функциональная проверка создала отдельный технический тест (копия 200 вопросов), 2 вымышленных студента, одно назначение и одну завершённую попытку. Затем технический тест снят с публикации, оба проверочных студента заблокированы; результаты оставлены как свидетельство проверки. Поэтому итоговые счётчики: 327 аккаунтов, 15 тестов, 1020 вопросов, 51 назначение, 2463 попытки. Это не нагрузочный тест.

SQL-слой VPS — `server/database.ts`: параметризованные запросы, ограниченный адаптер известных запросов D1, PostgreSQL-транзакции на одном соединении и повтор сериализационных конфликтов. `server/compat.sql` реализует используемые JSON-операции через jsonb и UTC-форматирование. JSON-тексты импортированных снимков остаются неизменными; проценты хранятся с двойной точностью. При добавлении новых SQL-возможностей нужно расширять адаптер и проверять поведение PostgreSQL.

Сборка новой версии: `npm ci`, `npm run build:vps`. Для публикации загрузить **только** `dist`, `build`, `server`, `worker`, `shared`, миграции и package-файлы в новый каталог releases; выполнить production `npm ci --omit=dev --ignore-scripts`; переключить symlink current, скопировать dist в `/var/www/finance-academy` с каталогами 755/файлами 644, перезапустить API и проверить Nginx. Не загружать `.local`, root-пароль, исходный экспорт или файлы выдачи доступов в публичный каталог. Начальный `install-release.sh` создаёт схему и импортирует данные; его нельзя повторно запускать поверх рабочей базы.

SSH-транспорт: `scripts/deploy/ssh.py`, приватные доступы `.local/vps-access.json`, закреплённый ключ хоста `.local/vps-known-hosts`. Изменение ключа хоста отвергается. Рабочие пароли не приводятся в документации.

Для прежней локальной разработки Worker скопировать `.dev.vars.example` в `.dev.vars`: пустой `MIGRATION_TARGET` отключает production-перенаправление только в локальном Wrangler. Команда `npm run deploy` теперь публикует только переадресацию Cloudflare; обновление приложения на VPS выполняется через сборку и выпуск каталога releases, описанные выше.
